## Build Philosophy

1. **Each phase ships something usable.** No phase leaves the app broken. After any phase, you can demo what you've built to the payment lead.
2. **Infrastructure before features.** Phase 0 sets up the schema, RLS and auth so that everything after it is fast and safe. The edition model in particular cannot be retrofitted.
3. **Magic moment first — as early as the dependencies allow.** Filtering to a population and exporting a disbursement file the partner accepts is the point of the product. It lands at the end of Phase 4, and nothing that is not on the path to it should be built before it.
4. **Test as you go.** Every task ends with a verification step. The RLS test suite in particular runs in CI from Phase 0 onward and must never be skipped.
5. **Progressive enhancement.** Simplest working version first, polish later. A correct filtered export beats a beautiful chart every time.
6. **Review before proceeding.** Push each completed phase as a PR and let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review it before starting the next. External review catches what the coding agent will not flag about its own work.
7. **Never silently change money data.** Duplicates are flagged, not deleted. Imports are transactional. If a record is ambiguous, a human decides. Any task that seems to require an automatic fix to beneficiary or payment data is a task that has been misunderstood.
8. **Test against the real file.** `Edo Coaches Payment Report.xlsx` is the fixture of record — 45 rows, two batches, 16 leading-zero accounts, 11 bank name variants, mixed name casing. If it round-trips, the import is right.

## Agent Session Guide

### How to Use This Roadmap with Your Coding Agent

1. **Start a session:** Give Claude Code the phase prompt at the beginning of each phase.
2. **Read selectively:** Each phase lists its Reference sections. Read only those — the PRD is long and loading it whole wastes context that is better spent on the code.
3. **Let it work:** The agent finds the first unchecked task, implements it, and marks it complete.
4. **One session, one phase where possible.** If you stop, resume from the last unchecked task.
5. **Push a PR for review.** When a phase is complete, open a PR and let a review agent such as [CodeRabbit](https://coderabbit.ai) review it before starting the next phase. Merge before continuing.
6. **Need more context?** If a task references something outside the phase's Reference sections, read just that section on demand.

### Session Tips

- **Don't read everything.** Each phase's Reference sections are deliberately narrow.
- **Don't skip tasks.** Ordering resolves dependencies; skipping creates them.
- **Run the app after each phase** before moving on.
- **Never skip the RLS test suite.** It is the one gate that protects the most sensitive requirement in the product.
- **Update the status line** in this file: `**Status:** X/94 tasks complete` and `**Current Phase:** Phase N`.
- **When in doubt about money data, stop and ask.** No task in this roadmap requires silently changing a beneficiary or payment record.

### Prompt Templates

**Starting a new phase:**

Start on the first unchecked task. After completing each task, update the checkbox to [x] in the roadmap file. Continue through the phase."

**Resuming after a break:**

Branch per phase: `phase-{N}/{phase-slug}`. PR title `Phase {N}: {Title}`, body containing the goal, the completed task range, what to verify manually, and the reference sections used. Let the review agent check it, address feedback on the same branch, and merge only when clean. If you are not using GitHub you can skip this — you give up automated detection of bugs, security issues and style problems the coding agent will not flag about its own work, so the per-task verification steps matter more if you do.

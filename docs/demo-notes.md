# Demo Notes — Phase 4

TASK-069 is not a coding task, and the roadmap calls it the most important item in this phase. It requires an actual session with the payment lead — this file is the scaffold for recording what happens there, not a substitute for it.

## Before the session

Load real historical data first — recognisability is what separates a system from a prototype. Run the real Edo import (`tests/import/fixtures/edo-coaches-real.xlsx` or, ideally, the actual historical file) into an active edition, accredit it, and configure a rate for the category before the payment lead sits down.

## The one question

**"Would you have run last edition's payments off this?"**

Ask it plainly. Do not lead the answer.

- Success is them asking for a column that does not exist, or objecting to a field's exact name or order — that means they're mentally operating it, not just watching a demo.
- Polite praise ("looks great!") without a specific correction is a failure signal, not a pass — it usually means they didn't engage with it as a real tool.

## What to record here after the session

- Date, who was present, which data was loaded.
- Their literal answer to the question above.
- Every specific correction, missing field, or objection they raised — verbatim where possible, especially anything about the disbursement file's column names, order, or the DRM disclaimer wording.
- Whether they asked for anything from Phase 6 (executive dashboard, etc.) unprompted — that's a signal about what to prioritise next, not a scope commitment.
